# 教师端改造设计（exam-maker v3）

- 日期：2026-08-27
- 范围：教师端首页 + 出卷向导，共 8 条需求
- 前置：本设计基于 2026-08-27 与用户的逐条澄清确认，全部决策点已收敛

## 一、背景与目标

exam-maker v3 是「数智命题师」多角色教学平台（教师 / 学生 / 辅导员）。本次改造聚焦**教师端**，把教师端从「单一出卷工具」升级为两大功能块：

1. **生成试卷**（出卷向导：真题/教科书 → 大纲 → 结构 → 命题 → 保存入库）
2. **考试、作业管理**（我的试卷卷库 + 考试管理实时跟踪）

目标：教师端信息架构清晰，试卷可分正式/错题推送，已分发可见、成绩发布可控、试卷可命名改名备注，出卷流程更可控。

## 二、需求清单与确认决策

### A 组 · 出卷流程

| # | 需求 | 确认的决策 |
|---|---|---|
| A1 | 「直接生成大纲」可选项增加 | **学科下拉**（预置：数学/物理/化学/计算机/英语/临床医学，可自由修改）+ **专业自由输入**；另支持**上传教科书**（PDF/DOCX）生成大纲 |
| A2 | 试卷结构可调整题目顺序 | step4 结构表格每行加 **↑ ↓ 上移/下移**按钮 |
| A3 | AI 备选题要生成完整题目 | 重写 `step5/alternatives` prompt，要求返回完整字段（type/score/chapter/topic/difficulty/content/answer/analysis），杜绝"计算三阶行列式"式残题 |
| A4 | 保存试卷命名 + 备注 + 可改名 | 保存时弹窗输入**标题 + 备注**；标题默认取课程名而非"试卷"；卡片上可**编辑改名 + 备注** |

### B 组 · 首页 / 考试管理

| # | 需求 | 确认的决策 |
|---|---|---|
| B1 | 「我的试卷」分两组 | 卷库内分两个 tab：**正式试卷 / 错题推送卷**（按 `is_practice`） |
| B2 | 已分发可见、成绩发布状态可见 | 卡片**内展开**分发名单（姓名/班级/学号/提交状态）；卡片显示**发布状态徽标** |
| B3 | 顶部统计框改造 | 四框 = **已提交 / 已批改 / 未批改 / 进行中的考试数**，全部可点开 |
| B4 | 新增「考试管理」 | 已分发**正式考试**的实时跟踪：用的哪套卷、提交/批改进度、成绩发布 |

### 已确认的关键决策点（不可再改）

1. **首页架构**：我的试卷 = 卷库（正式+错题推送两组）；考试管理 = 已分发正式考试的实时跟踪
2. **发布成绩机制**：独立发布按钮。批改+finalize 只存结果，学生端看不到；老师点「发布」后**整卷**学生才可见成绩。需新增 `published` 字段
3. **统计框四框**：已提交 / 已批改 / 未批改 / 进行中的考试数
4. **分发查看形式**：卡片内展开
5. **教科书处理**：PDF/DOCX，提取**目录 + 节选正文**喂 AI（全书全文不现实，token 超限）
6. **学科/专业**：学科下拉（预置可改）+ 专业自由输入
7. **备注用途**：教师内部备注，学生不可见
8. **考试管理范围**：只列正式考试（`is_practice=0` 且已分发）；错题推送卷在「我的试卷·错题推送」分组管理，不进考试管理
9. **「进行中的考试」定义**：已分发且**尚未发布成绩**的正式考试（发布后不算进行中）
10. **错题推送卷无发布成绩按钮**：练习卷学生做完即可看反馈，不设"发布"层

## 三、数据模型改动（`db.py`）

`papers` 表新增 3 列（迁移幂等，`ALTER TABLE` 判断存在才补）：

```sql
remark       TEXT          -- 教师内部备注（学生不可见）
published    INTEGER DEFAULT 0   -- 成绩发布状态 0/1
published_at TEXT          -- 发布时间（空 = 未发布）
```

对应 `create_paper` / `get_paper` / `list_papers` 读取与写入需带上新字段。

## 四、后端 API

### `platform_routes.py`

| 端点 | 方法 | 用途 |
|---|---|---|
| `/api/papers/{pid}` | **PUT** | 改试卷元信息：`title`、`remark`、`subject`、`duration`（改名+备注入口） |
| `/api/papers/{pid}/publish` | **POST** | 发布成绩：`published=1, published_at=now`，仅 teacher，校验所属 |
| `/api/papers` | GET（改造） | 每卷返回 `remark`、`published`、`published_at`、`is_practice`、`distributions`（明细：student_id/name/class_name/major/student_no/status/total_score/submitted_at） |

### `app.py`（出卷向导）

| 端点 | 方法 | 用途 |
|---|---|---|
| `/api/session/{sid}/step2/upload-textbook` | POST | 教科书上传（PDF/DOCX），复用 `extract_text_from_file`，额外提取**目录 + 节选正文**（头部章节 + 每章小节标题），存回 state |
| `/api/session/{sid}/step2/generate-syllabus` | GET（改造） | 入参增加 `subject`（学科）与 `textbook_text`；prompt 附带教科书大纲文本 |
| `/api/session/{sid}/step5/alternatives` | GET（改造） | 重写 prompt：输出完整题目字段，见 A3 |

### 学生端可见性改动（`/student/papers`、`/student/papers/{pid}`）

- `paper.published == 0` 时：`submission.total_score` 不下发（返回 `null` 或标记 `score_visible=false`），前端显示「成绩待发布」
- `published == 1` 时：正常返回 `total_score`

## 五、前端改造

### 5.1 首页统计框（`teacher.js` / `index.html`）

四框全部可点击：

| 框 | 统计口径 | 点击行为 |
|---|---|---|
| 已提交 | 所有正式+练习卷已提交数 | 进批改视图，筛选已提交 |
| 已批改 | status=graded 的提交数 | 进批改视图，筛选已批改 |
| 未批改 | status=submitted 的提交数 | 进批改视图，筛选待批改 |
| 进行中的考试数 | 已分发且 `published=0` 的正式考试数 | 进考试管理 |

### 5.2 「我的试卷」卷库（`index.html` 结构 + `teacher.js`）

- 顶部两个 tab：**正式试卷 / 错题推送卷**
- 正式试卷卡片：
  - 标题（可点编辑改名）、学科、题数、`remark`（若有）
  - **发布状态徽标**：未发布（灰）/ 已发布（绿）
  - 「已分发 N」可**点击展开**分发名单（姓名/班级/学号/提交状态）
  - 操作：📤 分发 / ✍️ 批改 / ✏️ 编辑（改名+备注弹窗）/ 🗑 删除
- 错题推送卷卡片：
  - 标题（`张三·错题巩固（xx）`）+ 🏷️ 练习卷 tag
  - 直接显示**学生姓名 + 班级**（单学生）
  - 作答状态：未作答 → 已提交 → 已批改
  - 可展开看逐题作答 + 对错 + 得分；批改入口；删除
  - **无发布成绩按钮**

### 5.3 「考试管理」（新视图）

- 列表：已分发的正式考试（`is_practice=0` 且有分发记录）
- 每行：考试名、用的哪套卷（题目数/总分）、分发 N 人、已交 X / 未交 Y、已批改 Z / 未批改 W、**成绩发布按钮 + 状态**
- 点击行可进入该卷分发/批改详情

### 5.4 出卷向导

- **Step 2**：
  - 新增「学科」下拉（预置可改）
  - 保留专业自由输入、年级、阶段
  - 新增「上传教科书」入口（替代真题解析的另一路径），生成大纲时把教科书目录/节选并入 prompt
- **Step 4**：结构表格每行加 **↑ ↓** 按钮（`syncStructureFromTable` 后重排 `no` 与 DOM）
- **Step 5**：保存试卷前弹窗输入**标题 + 备注**；默认标题取课程名

## 六、测试策略

无测试框架，采用**手动验证清单 + curl 冒烟**：

1. 重启服务后 curl 断言：
   - `PUT /api/papers/{pid}` 改名+备注生效
   - `POST /api/papers/{pid}/publish` 后 published=1
   - `published=0` 时 `/student/papers/{pid}` 不含 total_score
   - `GET /api/papers` 返回 remark/published/distributions
2. 浏览器手动清单（每条功能 → 步骤 → 预期）：统计框四框点击、试卷两组 tab、卡片展开分发名单、改名备注弹窗、考试管理发布成绩、出卷向导学科下拉+教科书上传、结构上移下移、保存命名备注。

## 七、范围外（本设计不做）

- 不改学生端/辅导员端核心流程（仅成绩可见性一处学生端改动）
- 不做试卷模板库、不做多学科跨卷联动
- 不改 AI 批改打分逻辑（错题推送自动警告误伤问题另立任务）

## 八、遗留问题（另立任务）

- 自动学业警告在小样本数据下误触发（学生均分 1.0 触发警告）——与本次改造无关，后续单独排查。
